# Dataceler — Daily Briefing Defaults

## Audience and intent

Audience: Dataceler leadership. The briefing must be an operating instrument, not an AI capabilities update.

The reader should understand within 30 seconds:

1. the current panorama;
2. the one priority that matters most now;
3. the measurable objective for the day;
4. the next action, accountable owner, deadline, and expected result.

## Required daily hierarchy

1. **Panorama:** one short status line each for Commercial, Deliveries, and Operations.
2. **Message-key:** one sentence that translates the panorama into a business consequence.
3. **Objective of the day:** one measurable result.
4. **Next actions:** one action, or two only when inseparable; each includes owner, verb/object, deadline, and expected result.
5. **Decision needed:** omit unless leadership must choose or approve something today.

## Editorial standards

- Prioritize revenue, pipeline, client delivery, operational efficiency, and risk.
- Use a single central theme rather than a collection of equal items.
- Treat “sem dados suficientes” as valid when supported by a named data gap; never fill space with generic commentary.
- Do not list agent capabilities, possible integrations, external news, trends, or broad discovery questions unless they change a decision today.
- Keep the briefing short but never sacrifice hierarchy: Panorama → Message-key → Objective → Actions.
- Every factual statement must originate in an authorized and recent source; summarize private data rather than quote it.

## Source strategy for recurring runs

Start with the smallest read-only evidence set: calendar, recent business email, delivery/project record, and documented pipeline or financial summary when available. Avoid attaching large general-purpose manuals to the scheduled run; use a compact retrieval routine instead.
